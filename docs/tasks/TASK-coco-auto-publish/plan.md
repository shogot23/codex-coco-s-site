## 手順

1. 公開手順に、今後の定期制作だけを対象とする継続承認と、失敗時の停止条件を追加する。
2. 既存の制作指示を維持し、現在の `site-work.json` 必須項目を反映する。制作の完全成功後だけ `gpt-6-luna` を後段担当として起動し、サイト取り込み、プレビュー、検証、PR、CI、merge、Pagesと公開URLの確認を指示する。
3. Claudeレビューを通し、repo文書をPR経由で反映する。その後、スケジュール設定を更新し、保存値を照合する。
4. `site-work.json` を持つ既存の納品物で取り込みの `--dry-run` だけを試す。該当物が無ければinbox外の一時フィクスチャで検証する。次回以降の成功実行で公開までの結果を確認する。

## 停止条件

- 制作失敗、必要ファイルや一致証跡の欠落、Lunaを指定できない場合はサイト工程へ進まない。
- 衝突、プレビュー・テスト・レビュー・CI・デプロイの失敗時は、状態を区別して報告し、成功と扱わない。
- 公開工程は隔離した単一writerで進め、元の作業ツリーには変更を加えない。

## 検証

- 文書・指示文のClaudeレビュー、`npm run typecheck`、`npm run build`。
- スケジュールのモデル・実行時刻・状態・指示文の再取得と照合。
- 既存パッケージの取り込み事前検証。実公開は行わない。
